# MSHA parser correction before final evaluation

The inherited quote-aware parser read 47,708 Mines rows and emitted four parsing problems; unescaped quotation marks in text swallowed records. Literal pipe splitting reads 92,000 unique mine records with zero parse problems. Every field is enclosed in quotes, so the corrected parser strips one outer quote pair from the analytical ID/code/numeric fields after splitting, preserving the original text fields and validating seven-digit mine IDs. Annual employment has 658,865 records. Both input files are unchanged.

A first literal-split attempt retained outer quotes and therefore filtered out all stone records. The secondary mine model became rank deficient, causing development to stop. The preliminary selection was preserved under output/models/pre_final_parser_fix before correcting the parser and rebuilding. No final-year model scores had been produced or inspected. Primary target/permit/highway/GDP values and the evaluation protocol did not change. The refreshed development selection is frozen only after this source correction. A non-UTF-8 character in an unused mine-name field prevents blanket text normalization, so only the analytical ASCII fields are normalized. Corrected capacity differences are exported to output/tables/msha_parser_correction.csv.

Gate 1's MSHA comparison reproduced the original parser and therefore did not independently establish complete record parsing. This finding supersedes that limited comparison. Corrected activity data remain secondary because current classification and USGS estimation dependence persist.
